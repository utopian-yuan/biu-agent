# 复现和验证

## E1 · 原问题

2026-11-20，在 `main@a35352e` 的旧工作区用临时账号上传虚构的「展签清点.md」，发送「展签清点.md 记录了什么？」。Chrome 暂停本条提交后，消息区已能找到该问题。检查输入框为空的断言在五秒后失败，实际值仍是相同的问题。旧实现把清理文字和附件放在读完全部回答事件之后。

## E2 · 修复复验

使用同一本地工作区、Chrome、临时账号和内置教学模型。浏览器在提交时先暂扣请求，随后放行真实材料读取，并在工具开始事件后暂停，分别检查两个时刻的界面。

| 操作 | 实际结果 |
| --- | --- |
| 带附件点击发送 | 请求尚未放行时，输入框已清空并获得焦点，问题下方已显示「展签清点.md」。工具读取期间，输入框仍为空，附件只在消息区出现。[读取期间截图](assets/composer-sent.png) |
| 等待回答时重新键入相同问题 | 再按回车没有增加消息。回答完成后，刚输入的同文草稿仍在。 |
| 重新生成较早回答 | 另一条未发送的文字和「下次核对.txt」均保留在输入框。 |
| 390 像素宽的新对话只发送附件 | 回车后，即使创建会话的请求尚未放行，默认问题和「窄屏练习.txt」已经在聊天区，待发附件区清空。随后回答能读出该文件。 |
| 提交无效 UTF-8 文件 | 服务端返回 422。原始文字连同两端空格、原附件恢复，历史中没有多出一条问题。若已写下一条，输入框保留新内容，点击「取回草稿」可切换。 |
| 已接收问题后的连接中断 | 让服务端实际处理问题，再丢弃首次响应。重试沿用同一请求编号，最终只有一条问题、一份附件和一条回答。 |
