# 用三份材料走完一轮助手对话

问题固定为「样品灯和导向牌分别到货了吗，有没有验收依据？」。先逐步核对，再替换其中一个环节。使用 Python 3.12，在仓库根目录运行 `uv sync --locked` 和 `uv run python -m examples.tickets.app`，打开 [工作台](http://127.0.0.1:8765/)，点击「注册账号」。设置用户名与密码后返回登录，再进入工作台。要逐步复现下文的固定调用次数，在输入框下方选择「教学演示」。

## 第一步 · 找到原始材料

打开「素材库」，用「材料助手」查看三份文件。文件是原创虚构材料。每行开头的段号是稳定引用，每份文件按实际字节计算 SHA-256。阅读文件名下面的具体段落，再给出你的预期判断。

| 资料 | 可回查的位置 | 这条记录能证明什么 |
| --- | --- | --- |
| [采购清单](../../examples/tickets/data/purchase.md) | P1、P2 | 采购两台样品灯、一块导向牌 |
| [到货记录](../../examples/tickets/data/receiving.md) | R1、R2 | 两种物品均签收，导向牌待安排检查 |
| [验收说明](../../examples/tickets/data/acceptance.md) | A1、A2 | 样品灯完成通电与数量检查，本次验收范围仅含样品灯 |

接自家数据时，先只实现两个操作。目录列出当前用户能看到的资料和位置，读取操作返回某一个位置的原文与版本。上游每次都要验证当前用户能否读该记录。可以用业务记录版本或不可变快照标识代替文件哈希。[来源适配实现](../../examples/tickets/corpus.py)

## 第二步 · 看上下文怎样组成

在「助手对话」选择「材料助手」，发送固定问题。回答后打开「本轮上下文」。首轮历史问题应为 0，再问「那导向牌呢？」后为 1。助手从当前问题、最多六条近期问题、智能体提示和已启用的能力开始。本地工具先返回许可目录，再把点名读取的原文送给模型形成依据。先前回答中的事实每轮重新取证。

在第一条回答上点击「重新生成」。同一个位置会显示新的回答，第二个问题仍排在它下面。第一条回答的历史问题数仍为 0。标识和文件版本由服务端记录。点回答里的段号，服务端会重新校验当前权限与文件版本，版本变化会要求重新取证。[上下文装配](../../examples/tickets/workspace.py) · [运行循环](../../src/biu_agent/agent.py)

## 第三步 · 核对工具究竟做了什么

打开一条回答的「本轮上下文」。离线教学练习使用「查看技能」「列出资料」，再读取六个段落。回答旁的出处可回查本轮读过的原文和版本。真实模型可能只选部分段落，评判依据是结论是否有足够原文支撑。

在「工具」中停用「读取段落」，新建对话，重复固定问题。可见目录仍可列出，回答应说明缺少可核对的依据。重新启用后再开新对话。切换「技能」可以调整核对顺序，读取能力仍由服务端决定。每轮默认最多 6 次推理迭代、8 次业务工具调用，单次本地工具返回 JSON 最多 4000 字符。[工具输入与输出](../../src/biu_agent/tools.py)

需要外部只读服务时，在「MCP 连接」添加可信的 Streamable HTTP 地址，保存、测试连接，编辑连接选择允许的工具，再进入「智能体」绑定这条连接。只会装配同时满足远端只读声明和本地选择的工具。远端身份可使用独立的只读凭据。MCP 返回的目录元数据和三份已登记文件的段落分别显示为工具调用和材料出处。

## 第四步 · 用同一个问题检查权限

切到「到货助手」，再次提问。素材库只剩采购清单和到货记录。它可以确认签收，当前材料不足以证明任何一件物品通过验收。切换智能体会开新对话。若在管理页实际撤销资料或读取能力，工作台会更新受影响智能体的权限版本，旧范围下的历史、回答原文与重新生成入口均停止提供内容。其他智能体的历史仍可访问。新对话按新授权运行。

每个注册账号管理自己的对话、配置和智能体。部署者如需进一步限制资料，在启动环境中设置 `BIU_MATERIAL_SOURCES=purchase,receiving`。任何智能体都只能读取部署授权与自身配置的交集。接入企业系统时，把部署授权换成宿主按当前用户求出的范围，继续在真实资料 API 上验证。

## 用本地文件走一遍

1. 新建一个 UTF-8 文件「展签练习.txt」，写两行虚构数据。第一行写「蓝色展签 3 枚」，第二行写「琥珀展签 7 枚」。
2. 在新对话的输入框左下点 **＋** 选择文件，问「请用 Shell 的 grep 在随附清单第一段查找固定词“琥珀”，给出匹配行和出处」。点击回答里的 **S1**，核对两行原文。打开「本轮上下文」可查看这次实际调用的工具。
3. 另发一份文件，再回到第一问点击「重新生成」。第一问仍只看到发问时的附件，后面的文件和问答保留在原位置。到另一段新对话中查看「本轮上下文」，前一段的文件不会列入范围。
4. 点左栏该对话旁的 **⋯**，在按钮旁重命名，刷新后检查标题。再次打开菜单可以取消或确认删除。在标题输入框、菜单或确认框按 Esc 可回到原按钮。确认删除后，两处历史列表同时更新，旧出处链接也会关闭。

每条问题最多 4 个文件，每段对话最多 12 个，每个文件最大 2 MiB，提取正文限 64000 字符。正文按段编号为 S1、S2 等。TXT、Markdown、CSV、JSON 和 LOG 使用 UTF-8，DOCX 读取文档正文，文字型 PDF 最多 64 页。图片和扫描件可先在本地转为文本。工具读取被选段落时会把段落发给当前所选模型。文件留在会话范围内，素材库展示的是智能体可用的教程原文。

「工具」里的搜索用于定位段号。Shell 的 `head` 返回段落开头，`grep` 做固定文本匹配，`wc` 统计传入段落的换行符、词和 UTF-8 字节数。智能体勾选并启用段落读取后，才可使用绑定的搜索和 Shell。每个智能体可单独关闭「允许本对话使用上传附件」。

## 七个工具怎样配合

打开新的「材料助手」对话。在「教学演示」模型中，逐行发送表格里的消息。每一行都会经过工作台的真实工具接口。在已配置的模型中也可以直接用中文描述同一操作。

| 发送到输入框的消息 | 核对结果 |
| --- | --- |
| `glob {"pattern":"materials/*.md"}` | 列出三份获准使用的教程文件及相对路径。 |
| `read {"path":"materials/receiving.md","start_line":2,"max_lines":1}` | 显示导向牌的签收记录，点 R2 回查原文。 |
| `write {"path":"work/展签.txt","content":"蓝签 2 枚\n琥珀 7 枚"}` | 回答下方出现第 1 版下载，打开后是两行文本。 |
| `edit {"path":"work/展签.txt","old_text":"7 枚","new_text":"8 枚","expected_version":1}` | 当前回答可下载第 2 版，上一条的下载仍为 7 枚。 |
| `grep {"pattern":"work/*.txt","keyword":"琥珀"}` | 定位到第 2 行，点击出处能查看「琥珀 8 枚」。 |
| `bash {"path":"work/展签.txt","command":"grep -F 琥珀"}` | Bash 输出「琥珀 8 枚」。「本轮上下文」记录实际调用的工具。 |
| `browser {"url":"biu://materials/receiving","find":"导向牌"}` | 通过材料页读到同一条 R2。改发 `browser` 可以先看目录。 |

输入 `bash {"command":"ls work/"}` 可列出本对话生成的文件，`bash {"command":"cat work/展签.txt | sort"}` 可以组合文本命令。`pwd` 显示会话根目录 `/workspace`。可用的命令还有 `echo`、`head`、`tail`、`uniq` 和 `wc`。上传的附件可用 `glob {"pattern":"uploads/**/*"}` 找到，再把返回的完整路径传给 `read` 或 `bash`。教程原文和附件只读，所有可写文件都归属当前对话的 `work/`，在回答成功时保存。重新生成早先的回答按当时的资料读取，写文件请另发一条消息。

需要读网页时，把公开 HTTPS 网址放进问题。可以要求助手查词、翻页或继续打开本轮已列出的同站链接。点回答里的行号会显示当时读到的文字以及「查看原网页」入口。浏览器提取网页正文，支持 HTML 和纯文本。

## 让自己的工作说明成为技能

点「技能 → 导入 SKILL.md」，文件可参考[材料核对技能](../../src/biu_agent/agents/skills/source-review/SKILL.md)。文件头的 `name` 是唯一标识，`description` 说明何时使用，正文写具体步骤。导入后到「智能体 → 编辑 → 可用技能」勾选它。技能列表会显示绑定的智能体，也可点击启用状态、编辑说明或导出文件。

开发者可以把内置技能放入 `skills/<name>/SKILL.md`。新账号初始化时会发现这些文件，已有账号可在「技能 → 内置技能」显式添加新技能或恢复内置正文，启用状态和绑定分别保留。模型选用技能时，调用会记入「本轮上下文」。[技能发现与运行](../../src/biu_agent/agents/skills)

| 要调整的部分 | 从哪里开始 |
| --- | --- |
| 将问题和历史组装成上下文，或扩展附件分段 | [context](../../src/biu_agent/agents/context) |
| 每次模型调用和工具执行时检查权限、记录调用 | [hooks](../../src/biu_agent/agents/hooks) |
| 选择会话历史、回答版本和预算 | [memory](../../src/biu_agent/agents/memory) |
| 修改助手的基础说明或技能正文 | [md_files](../../src/biu_agent/agents/md_files) · [skills](../../src/biu_agent/agents/skills) |
| 扩充授权范围内的本地工具或接入远端只读工具 | [tools](../../src/biu_agent/agents/tools) · [mcp](../../src/biu_agent/agents/mcp) |

## 复验这条路径

做一次综合核对。保留「到货助手」关于导向牌的答复，从回答里的出处回读 R2，确认它写的是签收和待安排检查。随后切回「材料助手」，找出验收范围的 A2。两份材料能共同解释本次验收只覆盖样品灯。若助手给出了导向牌的验收结论，应把那句话和它引用的原文放在一起检查。工具出现成功记录只证明读取发生过。

| 在界面看到了什么 | 可重复的代码对照 |
| --- | --- |
| 列表里少了一项，直接输入旧段号也读不到 | [项目权限与直接读取](../s03_permissions/README.md) |
| 「本轮上下文」出现技能名，回答仍缺材料 | [技能加载和资料授权分别改变](../s05_skill_loading/README.md) |
| 同一句追问能理解旧话题，但引用必须在本轮取得 | [历史窗口与错误引用](../s06_context/README.md) |
| 外部工具被列出或绑定，需要看服务端是否真的执行 | [MCP 回执与服务端计数](../s09_mcp/README.md) |

```sh
uv run pytest -q tests/test_material_workspace.py tests/test_material_connections.py tests/test_files_and_tools.py tests/test_conversation_tools.py
uv sync --locked --group browser
uv run --group browser playwright install chromium
uv run --group browser python -m tests.materials_browser
```

模型已配置时，可单独运行 `uv run pytest -q -m live tests/test_material_workspace.py`，比较两种范围的真实回答。离线测试、仅本机的 MCP / 模型协议测试与真实模型抽测在[本版证据](../../docs/features/FEAT-20261120-assistant-workspace/evidence.md)中分别记录。
